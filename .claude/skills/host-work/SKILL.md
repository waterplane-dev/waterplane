# waterplane host — durable work that outlives a session

Work that survives the process and the session that ran it: intents on disk, the tick that decides what fires, the backlog they are shown as, and the conversations they leave behind. Router: `host`. Reasoning: [host.md](../../../docs/notes/host.md); the cut-out narrative and measurements: [moved out of this skill](../../../docs/notes/host.md#moved-out-of-skill-host-work-2026-10-17). A weekly wall being a two-wall sequence rests on `limitretry.ts` (`host-core`).

- `backlog.ts` (a facade: `BacklogManager` over `backlog/backlogcore.ts` the shared state type, `backlog/backlogknobs.ts` the env knobs, `backlog/backlogwording.ts` the delivery sentences, `backlog/backlogtitles.ts` the title mark, `backlog/backlogstore.ts` config + boot + the switches, `backlog/backlogedits.ts` the row verbs, `backlog/backlogsessions.ts` the per-item sessions, cap, linger/reap and `deliver`, `backlog/backlogfollowup.ts` the flag-when-done sweep) — a VIEW of `intents/`, plus the prompt executor and the sessions work runs in.
  - **Every fired item gets its own conversation** (`openItemSession`, titled `backlog · <repo> · <label>`, `{kind:"repo", fresh:true}`); the shared `backlog · <repo>` session is retired . **No `/clear`** — a fresh process IS the clear, and it lands the item as its own reopenable conversation in `archive.ts`. The mark is the **PREFIX** (`isBacklogTitle`), never an exact title, and still recognition rather than a map (a restart orphans a map, not a title). A person who wants shared context SAYS so: `{kind:"session"}`, or `resume` (`--continue`). `serial` is set on every repo-target item — nothing else stops five due rows putting five agents in one worktree — and **only QUEUED work holds it** (`intentSerialHolders`: rows `starting`/`running`, sessions opened for queued work — origin or title mark — mid-turn, on a limit or with a question open); a hand session never does, and the held row carries the holder's id (`holderSessionId`). `ensureRepoSession`/`resolveRepoSession` survive only for the sheet's "open a session here" button (its bare `backlog · <repo>` title never closes — `closesWhenDone`) and a hand fire on a pre-`fresh` row; **automatic work adopts nothing.**
  - **The slot cap counts WORKING sessions.** `autoSessionCount()` is the cap's input, counted off the SESSIONS never a map, and only the working ones (`slotBusy`, R-automation-042: a row `starting`/`running` in it, a background shell `working`/`serverLike`, a background agent, or `autoFireBlocker` non-null — a turn, a box, a limit wall — overruled only by `REAP_CEILING_MS` of PTY silence). An idle session left open holds NO slot, so **nothing is ever closed to make room** (`closedBy: "auto-slot"` survives only on old closed rows). A `noSlot` row waits only while `max` sessions are WORKING (`autoSlotsWaitText`), and `backlog.list.autoSlots` carries every open id with `busy` as FACTS (`busy` absent = an older host = busy; the phone offers only the busy ones).
  - **Sessions END one automatic way, `sessions.remove()` and NEVER `kill()`** (kill has no closed-row on the other side of it): `lingerSweep` (`WATERPLANE_BACKLOG_LINGER_MS`, 10 min ; `remove(…, "auto-done")`) — **only for a session whose item said close-when-done** (`closesWhenDone` → shared `closeWhenDoneOf`: the opener row's `Intent.closeWhenDone`, found by `openItemSession`'s mark or the earliest row with that `sessionId`, else the synced global `CLOSE_WHEN_DONE_KEY` `waterplane.backlog.closeWhenDone`, **OFF by default**). Off ⇒ NOTHING closes it, and that stops no queued work. The per-item value is carried by `upsert()`, both adapters, `workItemInherits` and the agent route; it is edited through `edit()` (any state, `null` = inherit), never `update()`, so flipping it never re-queues.
  - **What may be reaped.** Never attached, never a row `starting`/`running` in it, and never one the CLI says is BUSY — `sessions.autoFireBlocker(id, idleFor) === null` is the free test (hook-, box- and silence-aware in one implementation). There is deliberately no "ever attached" exemption. **The one thing that overrules the CLI's word is `REAP_CEILING_MS` (6× linger) of PTY silence** — a lost `Stop` leaves `turnActive` set for the life of the process. **A BACKGROUND shell still `working` or `serverLike` (`info.shellList`, `@waterplane/shared`'s `shellBucket`) refuses `reapable()` outright**, logged, before `autoFireBlocker` is even asked . **This refusal is NOT overruled by `REAP_CEILING_MS`**; a `foreground` shell (the running turn's own command) is not this check's business. **A background AGENT (`info.agents`, non-empty) refuses it the same way** . **A hooked session lingers from `idleSince`** (the turn's end).
  - **Dead session ⇒ `queued` if `diedAtLimit`, else `failed` — never `done`; EXCEPT a row in a session of its own, which FOLLOWS the resurrection and is never requeued** (a requeue runs the item twice). That exemption keys on `Intent.followed`, persisted, NOT on the target: the re-aim rewrites the target. It follows **EXACTLY the session that replaced it** (`SessionManager.revivedSessionFor` records dead id → new id in `doResurrect`), never "the newest session in that cwd".
  - **A create off the WIRE never wears the `backlog · ` mark** (`withoutBacklogMark`, applied in `routes/session.ts`): the mark is the only thing the cap, the reap and the linger sweep read.
  - **Only a FIRST-step `retry` may re-run an item** (`retryableStep`): `retry` means "provably nothing was typed" about that STEP, and a chain's step 2 arrives with step 1 already run — a requeue types it into a second session. **`ExecutorResult.step` must travel**: `fire()`'s Stop shortcut is valid only for step 0 . `backlogstore.test.mjs`, `backlogsessions.test.mjs`, `scripts/e2e-backlog-slots.mjs`, `scripts/e2e-resurrect-item.mjs`.
  - **Flag for follow up when done** (`Intent.flagWhenDone`, absent = off, no global; threaded exactly like `closeWhenDone`, merged rows flag if ANY member did): `backlog/backlogfollowup.ts` `followUpSweep` flags the session a row OPENED (`openerRow`, shared with `closesWhenDone`) with `{by:"launch", item}` ONCE per row, only when the row is `done`+ok and `slotBusy` is false — a failed or limit-stopped row never. Applied row ids persist (`followup-launched.json`, capped) so a cleared flag does not return and a restart does not re-flag. `BacklogManager.lingerSweep` runs it FIRST, so nothing closes a session ahead of its flag; fan-out children carry the flag from the run. `followupsweep.test.mjs`.
- `agentintents.ts` + `agentfollowup.ts` + `agentexposure.ts` — **later work an AGENT posts**: `POST|GET|DELETE /api/agent/intents[/<id>]`,
  loopback-only, never a browser (`Origin`/`Sec-Fetch-Site`), never proxied (`tailscale serve` forwards to 127.0.0.1 — the forwarding headers refuse it). **`postClientDraft` is the ONE client path into `IntentManager.post`** — the socket's `intent.post` calls it too, and `peers/` with a `peer:` origin: contain the cwd, authors forced `hand`, `pastBudget`/`budgetPass` stripped, and `origin: "agent"` written ONLY by this route (stripped off the socket). At-most-once by the caller's `key`: the row id IS `agent-<key>`, so a retry returns the same row, forever. One-offs only — a recurring rule is refused in words. The answer's `fires` is `whenWords` (`shared/schedule.ts`, the send sheet's own). DELETE cancels only a row an agent posted. **`POST /api/agent/backlog`** goes through `addClientBacklogItem`, the socket `backlog.add`'s own body, and marks the row `manual`: rung 1 holds it for ever, only the person's `fire` (`runNow`) starts it. `agentintents.test.mjs`, `scripts/e2e-agentintent.mjs`.
  - **`GET /api/agent/exposure` + `POST /api/agent/exposure/triage` (`agentexposure.ts`) can MARK a crash group / finding seen, investigating or fixed, never clear it**; same gate, and the POST needs a resolving live session (`resolveFollowUpSession`, same status and sentence) whose repo is recorded in `by`. The GET lists OPEN findings; `?all=1` adds accepted / fixed ones and `staleMarks`. `fixed` is refused for a finding with no `appVersion`. R-monitoring-004.
  - **`GET /api/agent/queue` + `POST /api/agent/queue/order`** — the waiting rows, and their order: waiting rows only, 2-200 ids, all-or-nothing.
  - **A called-off (`canceled`) row goes over the wire as `failed` with `BacklogItem.calledOff`** (`intents/adapters.ts`, `"agent"` when the agent withdrew it) — no third terminal status; the phone treats it as settled, not failed.
  - **`POST /api/agent/followup` can SET a follow-up flag, never clear it** (no DELETE, empty reason refused — the only way a flag goes away stays a person's tap); same `agentCallerRefusal` gate; the session is named by `session`, else the longest cwd that is the caller's `$PWD` or a parent (`resolveFollowUpSession`, pure). R-sessions-044.
- `workbacklog.ts` + `workbuild.ts` + `workassess.ts` + `workschedule.ts` + `workintent.ts` — the WebSocket work-message handlers under `routes/work/`: every handler that carries an ackId is `durable` or joins the in-flight map, and a backlog add refuses a lost ack with `AckLedger.preLossRefusal`. - `peers/jobs.ts` + `peers/agentpeer.ts` + `peers/store.ts` — a job on ANOTHER desktop: the loopback twin of `agentintents.ts` (`agentCallerRefusal`/`agentBasics` reused). `peers/store.ts` is the pairing ledger (`peers.json`, 0600); the jobs ledger `<state dir>/peer-jobs.json` (`peers/jobs.ts`) is written BEFORE the first forward, so a crash between POST and write re-forwards under the same key and the peer answers `existing` (idempotency). A peer token unlocks only `/api/peer/*` and a job never restarts the peer's live daemon (CLAUDE.md). ⇒ [peers](../../../docs/notes/host.md#peers--delegating-a-job-to-another-waterplane-host)
- `fanout.ts` — one prompt → N repos, fresh session each, dirs validated against `discoverTargets()`
  (unknown paths silently dropped). A run is N intents sharing a `groupId`, so `FanoutRun` is
  REBUILT from rows and survives the daemon. `followUp()` never spawns. A scheduled sweep gets a
  fresh run id per occurrence.
- `weekburn.ts` + `routes/apiweekburn.ts` — the week-end burn: repos the person PICKED for this week
  (`weekOf` = that week's reset; a new week starts with none, `recurring` only asks again) get lazy
  backlog rows, ONE live row per repo, capped per week, `origin: weekburn:<weekOf>`, a weekly
  `budgetPass` to the reset. Ordinary auto rows: serial, slot cap and halt still hold — never fan-out
  (its children skip the gates). Posts nothing without a fresh weekly reading, past `stopPct` or

- `intents/` + `adapters.ts` + `manager.ts` + `contract.ts` + `clock.ts` + `disk.ts` + `write.ts` + `requeue.ts` + `ladder.ts` + `fire.ts` + `watch.ts` — **the durable Intent store**: one file, one tick, one lifecycle, for every piece of
  deferred work. REPLACES `schedule.ts` and `launch.ts`; `adapters.ts` speaks the old vocabularies (`launch.*`/`schedule.*`/`backlog.*`, which the shipped client still sends) and **is the only path for THOSE** — `agentintents.ts` posts to `IntentManager.post` (`postClientDraft`) / `BacklogManager.add` (`addClientBacklogItem`) directly. `manager.ts` (the facade) and its slices own the store (`disk.ts`), the tick's pass (`ladder.ts`), reconciliation (`watch.ts`) and every transition (`fire.ts`, `write.ts`, `requeue.ts`); executors are injected from `server/intentDeps.ts`. `packages/host/test/intentsched.test.mjs`, `scripts/e2e-schedule.mjs`, `scripts/e2e-timedwork.mjs`.
  - **Store, ack, at-most-once.** **`op.ack ok` means on DISK**; **`starting` is written BEFORE the executor**; **at-most-once by intent id, forever**; **nothing is armed with a timer** (a tick re-asks `intentVerdict`, so restart/sleep/DST cannot mis-fire it); **eviction is compaction, never deletion of un-run work** (what leaves is appended to `intents-archive.jsonl`). `<state dir>/intents.json` is **schema 3** (`{schema, intents}`, `STORE_SCHEMA`, `intents/contract.ts`) with a `*.bak` beside it — both older shapes read: 3 = the legacy timed PARENTS were set aside once (`foldLegacyWorkParents`, `intents/disk.ts` , once ever, not once per boot); 2 = every repo target re-read as `fresh`. Migrates `launches.json` / `schedules.json` on first boot, renaming each `*.migrated`. `noteSession(id, sid)` is how an executor that OPENS a session names it on the row before the delivery finishes proving itself (and takes the completion baseline there).
  - **Reconcile.** **A `sessionId` is per-boot for a PTY and is NOT under tmux**, so `reconcile()` runs after `sessions.rediscover()`. It asks the CLI's log about a `starting` row — **never a blanket requeue** — and about a `running` one: `landed` + the session came back ⇒ RE-ADOPTED `running`, its Stop or the silence sweep settles it — **never `done` off the log alone** (the log proves delivery, not an ending); `landed` + session gone ⇒ `failed` saying the session was lost (at the limit ⇒ it follows), never `done`. `sweepRunning` also waits out `awaitingInput` (an unparsable dialog) and a copy-mode pane (idle `null`), treats a session hooked by a `Notification` alone (`turnHookSeen` false) as unhooked, and FAILS a hooked row silent past `REAP_CEILING_MS` (a lost Stop — never `done`) — except a row whose net retry gave up (`intents/watch.ts`): that one is STALLED, stays `running`, is never re-fired or failed, and the next real turn end completes it.
  - **Budget waiver and pass.** `waive()` sets `pastBudget: {until}` (latest tripped reset; refused with none, or archived); the tick drops an expired one; kept through `starting`, cleared once `execute()` returns except `retry` (reconcile's `absent` keeps it); carried by `upsert` and to the F14 child; a MIXED merge is refused; `intent.post` strips it. **`IntentDeps.budgetOver()` (every tripped ceiling) rides beside `budgetBlocked`**, and `workItemInherits` stamps `budgetPass` from `lastOccurrence`, so a recurring before-reset rule's child is not re-held by the cap its parent was exempt from.
  - **Run now.** **A bulk verb never reaches `runNow`**; `runNow` is one row's tap. It does not spend an occurrence and REVIVES a spent one-off; a terminal one-off is not ARMED (`nextAt` null); a one-off (`!ruleRecurs`: `once`, or `weekly`/`window` with `oneShot`) arms from the GRACE FLOOR, a recurring rule from now.
  - **The slot rung.** **The cap on automatic sessions is a RUNG, not a side door** (`noSlot`): `IntentDeps.autoSlotsFree()` + `autoSlotsDetail()` (the numbers, like `budgetDetail`), and `base.autoSlotsFree` is **decremented per fire within a pass** (the `hostBusy`/`busyCwds` trick ). **A freed slot is never handed out mid-pass** — the next tick's fresh `autoSlotsFree()` gives it to the first row in order. **The whole ladder is re-asked after ONE microtask yield (`await Promise.resolve()`) before each `go` claim** — a kick runs the pass synchronously only that far, so a synchronous batch of writes lands before any claim; busy facts are re-read and the ladder re-asked, MONOTONICALLY. **`packages/host/src/localslot.ts` is rung 4.55 `localModel`** (R-intent-local-001): automatic local-model rows wait while `IntentFacts.local.free <= 0` (a local TURN working, or a local row `starting`/`running`; synced cap, default 1) and `localHold(row)` — synchronous, claims nothing — holds until Ollama has the model loaded, never a fallback model; a person's start is told, never refused ([host.md](../../../docs/notes/host.md#the-local-model-gate--rung-455-localmodel)).
  - **A chain (`after`) reads FOUR facts and the manager supplies all four or none** (`chainFacts()`, one walk per pass): `settled` (live rows + archive tail), `knownIntents` (what turns a dead predecessor into a FAILURE instead of a row that waits for ever), `chainWaits` (the edge list a cycle is visible in) and `neverSettles` (`isRecurring` rows: a standing rule never terminates, so a chain behind one FAILS naming the rule). **Every one is optional and absent means "nobody said" ⇒ WAIT**. The archive read is a **BYTE TAIL, `ARCHIVE_TAIL_BYTES` 256 KB**, cached on the file's size+mtime (append-only ⇒ unchanged = nothing compacted); **past the bound a predecessor reads as GONE and the row FAILS with a sentence — the intended trade**. A row `remove()`d while still QUEUED is archived but NOT known: it never finished.
  - **Hours and the grace floor.** **`hours` moved `armFrom`'s grace floor** (`graceFloor()`): the grace counts from the window OPENING — widened by a day only when the floor is shut and `hoursOpenFrom` says the opening is still within the grace, and the widening only makes a candidate VISIBLE (`intentVerdict` does the arithmetic). **Never a second local clock** — `inHours`/`hoursOpenFrom` are the one implementation, and a second would disagree across DST. `hours`/`guardWindow` need NO line in `adapters.ts`: the RULE is carried whole both ways. A scheduled CHAIN does need a line: `ScheduleAction.backlog.steps` is the ONLY slot on the wire for turns 2..n, read as `action.steps ?? [action.text]` and written back by `intentToSchedule` so renaming a rule cannot shorten it (a SWEEP still runs `steps[0]` alone).
  - **F14 and one-offs.** **`workItemInherits()` — a RECURRING schedule's `backlog` action gates the CHILD, not the making of the row** (instantaneous, never busy): the whole chain, `holdForHost` and `resume` travel; `serial` is already on every repo-target item. **RECURRENCE decides the list, and a ONE-OFF RUNS ITSELF** (`isTimedWorkRow`): `execute()` routes to `workItem` only when `isScheduleRow`, so a one-off aimed at one place falls to `freshSession`'s awaited backlog branch — its own session, no child row, no second account of one piece of work. `intentToSchedule` answers `null` for one — the wire is UNCHANGED, `scheduleToIntent` and `schedule.save` still take a one-off — and it rides `backlog.list` with `BacklogItem.at`/`holdForHost` instead. **`upsert()` CARRIES every host field `ScheduleEntry` cannot say** — the naming pair × 2, `order`/`handOrdered`/`archived`, the requeue history — when the draft is silent: it rebuilds from the DRAFT (`revivedShape`'s rule, one path over). `fire()` only returns a hand-run row to `queued` when it HAS a next run, and `update()`'s one carve-out revives a **failed** timed row patched with a **trigger** (*drop the clock*), never a `done` one and never on words alone.
  - **`requeueFailed` — a FAILED row can be PUT BACK** (failed ONLY, every other state refused in a SENTENCE; `result` is KEPT, `origin` is never rewritten — provenance is `requeues[].by`, whose value is the CALL SITE's: `run` for the two verbs that fire in the same breath, `hand` for a tap that waits, `assess` for a proposal; a spent one-off's clock is DROPPED and the entry SAYS so; the count is the UNCAPPED `requeueCount`, never `requeues.length` (capped at 5); and **NO `requeued` event** — that channel is the usage limit's "Backlog paused"). **The LADDER is asked first** (`wouldNotRun`, over `revivedShape`'s copy): a `fail` verdict, `sessionGone` and an `archived` row are REFUSED in words quoting the detail — put back, they stop again next tick or wait for ever; the ordinary waits (budget, slot, `serial`, hours, a live chain) are NOT refused. A mismatched `failedAt` is refused too — `failed` is a state, not an event. `runNow` on a failed row puts it back first, **`{kick: false}`** (the assessment's bulk apply, `assess/hassapply.ts`, does the same and calls ONE `intents.kick()` after), and **`fire()` returns on an `inflight`/`starting`/`running` row**; `done`/`canceled` stay refused.
- `archive.ts` — every conversation the CLI ever wrote for a repo, read off disk. Closing a session
  was never a delete. Remembers nothing; the filename IS the conversation id. A backend with `sources.conversations` lists (and, with `remove`, deletes) its own through `sourceList`/`deleteConversation`; `pickRefusal` says in words when none lists. **`deleteArchived` is
  the ONLY way to lose a claude conversation in this app** (a plugin backend's goes through `deleteConversation`) — bare-id regex, per-row confirm on the phone.
- `convfork.ts` — a conversation cut at a TURN, written under a new id. Cut after the WHOLE turn;
  rewrite **`sessionId` and only that** (`session_id` is PROVENANCE). `pruneStranded()` prunes only records about a turn the cut removed (file-history snapshots, compact `system` rows — measured over 7,076 cuts, not enforced in code); in those cuts it never pruned a `user`/`assistant`/`attachment` record (the code prunes any record naming a uuid absent from the prefix, `convfork.ts`). Source read-only, tmp+rename, fresh uuid.
