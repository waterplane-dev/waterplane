# waterplane host — the router and the frame

One line per module naming the sub-skill with its rules, the frame every host task
touches, and nothing else. Small on purpose: it was 77k once, in the
window every turn.

**Which sub-skill holds a module** — generated by `tools/skillmap.mjs` and checked by
`tools/claudemd.test.mjs`, so it cannot rot. A module on two lines has rules in both:

- `host-core` — agents.ts, answergate.ts, boxes.ts, budgetwatch.ts, builtin.ts, claude.ts, convid.ts, core.ts, ctxseries.ts, deliver.ts, deliverknobs.ts, deliverproof.ts, deliverreturn.ts, deliverrun.ts, deliverscreen.ts, delivertypes.ts, drive.ts, echo.ts, halt.ts, haltall.ts, health.ts, knobs.ts, links.ts, livemode.ts, pluginapi.ts, pluginloader.ts, pluginregistry.ts, record.ts, resume.ts, roster.ts, screenlog.ts, sessionSearch.ts, sessions.ts, settle.ts, setupcontrib.ts, shells.ts, sidechannel.ts, tmux.ts, turn.ts, types.ts, wall.ts

**…by symptom**, when you know what is wrong, not where:

- a prompt was typed but never confirmed, or typed twice → `host-core` (`deliver.ts`, `settle.ts`)
- deferred work fired late, twice, or not at all → `host-work`
- the daemon spent money with nobody watching → `host-spenders`
- a token, context, cost or limit number is wrong or missing → `host-ledgers`
- the CLI's screen was misread (a box, a banner, a question) → `heuristics`
- uploads, artifacts, builds, screenshots, dictation, machine readings → `host-machine`
- the wire, an ackId, a new message type → `protocol`
- a plugin answered (or failed to) a box, or is listed as broken → `host-core` (`answergate.ts`)

**Splitting `sessions.ts`, `intents/manager.ts`, `main.ts` or `deliver.ts`:** load `refactoring`;
the cut is decided in [host-architecture.md](docs/notes/host-architecture.md).

**The security boundary is NOT here and is never a skill** — `origin.ts`, `auth.ts`,
`paths.ts`, `scaffold.ts` and the containment guards are in CLAUDE.md, always on, because
a rule you must load can be acted without. Same for its newer companions —
`deviceledger.ts` (per-device tokens), `lanid.ts` + `authroutes.ts` (LAN identity,
pre-auth verify), `ratelimit.ts` (the shared pre-auth bucket) and `pair.ts` (QR mint/redeem) — described in
[protocol-and-security.md](docs/notes/protocol-and-security.md), not routed to by module name.

**The frame every host task touches.** Here because routing a message, booting the
server and the ackId ledger are what no slice can avoid:

- `routes/` — the client-message table, keyed by `t` (`session`, `work/`, `system`).
  `durable: true` wraps the handler in `durableOp`; `contain: "cwd"` resolves the client's directory
  through `containRepoDir` first. Everything a handler may reach for is `HostCtx`.
  **An unknown `t` is ignored, never thrown** — the wire is versioned.
- `env.ts` — `ROOT` and the three `.env` loads, **`main.ts`'s FIRST import** so every `WATERPLANE_*`
  knob a module reads at import sees the files; the merge is `envfiles.ts`: the shell beats every
  file, a later file beats an earlier one (per-user config > repo `.env` > legacy). A new knob may be read at import — never import a host module
  ahead of `env.ts` in `main.ts`, and keep `env.ts`'s own imports env-free.
- `main.ts` — the entry point: every construction in boot order with its singleton
  registration and `DOCTOR` gate, the `ctx` assignments, `handleClientMessage`, `main()` (bind
  selection, the public-bind refusal). It exports nothing; its functions live in `server/`.
- `server/` (`ctx.ts`, `clients.ts`, `intentDeps.ts`, `intentEvents.ts`, `billingwire.ts`, `scan.ts`, `deliveries.ts`, `wsops.ts`, `liveness.ts`, `sessionEvents.ts`, `http.ts`, `shutdown.ts`, `firstapp.ts`, `ctxseal.ts`) — `main.ts`'s pieces, factories over `ServerCtx`
  (`ctx.ts`, types only). A factory reads `ctx.<x>` at CALL time, never destructures it at
  construction, and registers nothing at import; `main.ts` assigns every member right after its
  definition. `clients.ts`: sockets, `send`/`broadcast`, the watched set,
  the notification feed, `notify()`.
  `intentDeps.ts`: `makeIntentDeps(ctx)`, the `IntentManager` deps literal with the executors and
  the sweep-dirs cache as closure state; `main.ts` keeps `new IntentManager(makeIntentDeps(ctx))`.
  `intentEvents.ts`: `createSnapshots(ctx)` (the store's snapshots, `padNotesFor`) and
  `wireIntentEvents(ctx)` (the four `intents.on`). `scan.ts`: `createScan(ctx)`, the outbox/image/
  auto-pull baselines and scanners, `announceBuild`, and the `autopull.on("item")` it registers —
  called right after `new AutoPullManager`, which stays in `main.ts`.
  `deliveries.ts`: `createDeliveries(ctx)` — `startPrompt` (types a create's first prompt; only a
  provably-`retry` failure may be re-queued), `deliverChain`, `deliverInput`, the
  open-delivery re-send callback, `wireDeliverySettled()` and `deliverySnapshot`; `new OpenDeliveries`,
  `setOpenDeliveries` and the `DOCTOR`-gated `.start()` stay in `main.ts` around the wire call.
  `wsops.ts`: `createWsOps(ctx)` — the in-flight maps, `sendOpAck`, `durableOp`, `containRepoDir`
  and each `/ws` server's connection handler. **`containRepoDir()` is the ONE gate on a
  client-named directory** — inside `ROOT` or a discovered worktree, else refuse, never guess.
  `durableOp()` = at-most-once per ackId; **thrown ⇒ not remembered, `ok:false` ⇒ remembered**;
  `new WebSocketServer` stays in `main()`'s `attachWs`.
  `http.ts`: `createHttp(ctx)` — `MIME`, the auth endpoints, `serveStatic`, the per-bind request
  `handler` (origin/Host gate first) and `listenWithRetry`;
  the public-bind refusal and `createServer` stay in `main()`. `shutdown.ts`: `installShutdown(ctx)`
  — the SIGTERM/SIGINT flush (its ORDER is behaviour, pinned by `hostpins`) and the two process-error handlers.
  `firstapp.ts`: `createFirstApp(ctx)` — the first-app job (`onboard.ts`, persisted, `onboard.progress` frames), called AFTER
  `intents.start()` so a job resumes into a running store; never under `DOCTOR`.
- `acks.ts` — the ackId ledger. Persisted, TTL 45 min, flushed on SIGTERM. Restarts are routine.
- `api.ts` — the HTTP frame: CORS reflection, preflight, dispatch over `routes/apiroutes.ts`'s one
  table. A route is `route(method, pattern, handler)` in a domain table (`routes/apisystem.ts`,
  `apihost.ts`, `apisession.ts`, `apistats.ts`, `apirepofiles.ts` + `apirepowork.ts` under the
  `/api/repos/:id/*` scope; helpers in `apiio.ts`, the matcher in `apitable.ts`). A handler returns
  `false` for "not mine"; first match wins; a new route is a new line in
  `packages/host/test/apiroutes.test.mjs`. Only `api.ts` of the flat modules may import `routes/`.
  Artifacts over `STREAM_MIN` are **piped, not buffered**; resumability rests
  on `accept-ranges`, a correct `content-range`, **416 not 200** past the end, and `if-range` — on the
  buffered path too. `artifact?…&stat=1` answers mtime+size and no bytes, behind the same gate.
