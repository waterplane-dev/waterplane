# waterplane host — the ledgers

The counted half of the host: every token, context, cost and limit figure this desktop keeps on disk, claude's and opencode's, kept apart. **Every reading degrades to ABSENT, never to a plausible wrong number** — the rule behind each bullet below. Router: `host`. Reasoning: [host.md](../../../docs/notes/host.md); the cut-out measurements and incident prose: [moved out of this skill](../../../docs/notes/host.md#moved-out-of-skill-host-ledgers-2026-10-17). Every reader honours `CLAUDE_CONFIG_DIR` through `claudeconfig.ts` (below) — never hard-code `~/.claude`.

- `ctxlog.ts` · `ctxcursor.ts` · `ctxupdate.ts` · `ctxproject.ts` · `ctxagents.ts` · `usagerecord.ts` — how full the window has been, off the log, which is DATED.
  **`ctxlog/usagerecord.ts` is the ONE reader of a usage record** (`usageRecordOf`): `<synthetic>` skipped, `message.id` deduped through the caller's set, the four kinds + 1-hour tier, and `carried` — the ANCHOR is the first record with `carried > 0`, never an output-only one. `tokenscan.ts`, `ctxupdate.ts`, `ctxagents.ts`, `transcriptparse.ts` and `backends/overhead.ts` all ask it; `tools/usagerecordpins.test.mjs` refuses `cache_read_input_tokens` spelled in host code anywhere else (`sidecarclaude.ts` reads `claude -p`'s JSON, another shape). A fix to a record rule goes there, once.
  Code: `ctxlog.ts` is a barrel; the four slices are `ctxlog/` (`ctxcursor.ts` owns `MAX_READ`, 24 MB; `limitlog.ts` has its own, unrelated 512 KB one). Refuses three plausible-and-wrong charts: a STREAMING turn repeated under one `message.id`, the rejection's `<synthetic>` zero-usage turn, and a SIDECHAIN. Incremental via a cursor whose `consumed` is the offset past the last NEWLINE. **The window is not in the log and is never invented.** `ContextLog.carried` (what the first request carried, `ctxcursor.ts` `foldCarried`) reads the `attachment` records written BEFORE the first assistant usage through a substring pre-filter, anchored on that usage's input+cache_creation+cache_read; the INITIAL set only; a later delta is a changed KIND (`laterDeltas` counts kinds, `laterKinds` names them), never folded; per-prompt hook context and an identical re-send (a resume re-attaching the initial set) are not changes; `prompt_snapshot` is an undocumented record, optional, first seen wins; a truncated log (`MAX_READ`) KEEPS `carried` (the head is read from byte 0).
  - **What the session SPENT** is a different number: `usageTok` is a RUNNING counter (never a fold over the capped `samples`) and includes the OUTPUT the readings exclude, and `agentUsage()` adds the Task tool's own logs, **read WHOLE, forward in `MAX_READ` chunks, never tail-capped** — a tail is a total that starts in the middle and looks complete, which is a wrong number, not a floor. The agents are all in `<conversation>/subagents/agent-*.jsonl`. **Read BEFORE the "log has not moved" early return** (an agent writes while the parent log sleeps); a missing directory is a measured ZERO, any other failure publishes NO total rather than one the agents are missing from. The size check on each poll is a `stat`, never a read.
  - **The SPLIT rides that same pass** (`split`, and the agents' own): four kinds plus a REQUEST count, accumulated behind the identical guards so `tokenTotal(split)` IS `usageTok`  — never a second tally. Its record rules must stay `tokenstats.ts`'s exactly (all-four-zero dropped, 1-hour tier READ), or the per-session and all-sessions screens divide by different denominators.
  - **The COST, PER RECORD** (`cost`, `unpriced`, on the agents too): the rate belongs to the model that ran the request and the day it ran on, both of which change inside one conversation — pricing `split` as a whole would charge the whole history at `cur.model`, the NEWEST. Same bag as the split, so money and tokens cannot come from different records; an agent is priced on ITS OWN model. **Nothing priced ⇒ NO cost, never a breakdown of zeros** , the money rides only where the subagent directory was READ (the `usageTok` rule ), and what no rate covered is COUNTED, never charged zero.
  - **Every sample carries WHAT it was made of and WHO made it**: `kinds` (this request) AND `cum` (the running counter) ; and a model INDEX into a table keyed by **ALIAS** (`normalizeModel` ; pricing still uses the RAW id). The table is sorted by volume on the way out and **every index is rewritten with it**, into NEW objects (`downsample` returns the cursor's own array under the cap).
  - **The ROSTER and the agents' time.** `agentUsage` keeps a roster (`runs`): one dated, sized, attributed row per agent log — an agent with no usable timestamp is in the TOTAL and off the roster (spend, not a moment), and `withAgentRuns` folds an agent's model into the table by alias, appending one the parent never ran. **The agents are DATED, so their spend is placed in time**: `agentCumOf` merges every agent log's running total by timestamp into `agentCum` (≤120 points, each bucket's LAST kept, so the last point IS `agentTok` — an undated record rides into its log's next dated one, an undated log onto the final point), and `agentEnvelope` folds the agents' windows onto the spark's own readings as `agentEnv` (max per reading's stretch).
  - **What the GAPS cost** (`coldStarts`, the same pass): a request that comes back to an EXPIRED prompt cache re-WRITES the window it had already paid to cache, and **the curve cannot show it** — the window is the same size either side. Recognised by `shared/sessioncost.ts`'s `isColdRebuild` and priced per record, with the PREMIUM over re-reading kept apart from what the writes cost (only the premium is money the clock spent rather than the work). The two traps that fake WARM and `REBUILD_READ`: rule in the `shared` skill; here the compaction trap is defended twice — the boundary flag AND the arithmetic. **A rebuild is NOT a spark mark and not a tick on any chart**.
  - **What the COMPACTIONS did** (`compaction`, the same pass): priced per record like everything else; the shed/saved/rebuild rule is in `shared`. **The summarisation request is NOT in the log** (the summary is a `user` row with no usage), so the cost is a floor and nothing subtracts the two sides into a net. A boundary missing either end of the drop OR its trigger goes to `unmeasured` and enters no row — `count + unmeasured` minus the manual ones would assert a trigger nobody recorded. 
- `transcript.ts` · `transcriptlog.ts` · `transcriptparse.ts` · `transcriptscreen.ts` · `transcriptturns.ts` — the CLI's conversation log as the reader's document.
  Code: `transcript.ts` is a 35-line barrel over `transcript/`, cut by subject like `ctxlog.ts` — location and record predicates / the parse / TUI chrome / turns the log does not hold. **The default document is `lite`** (names, labels and ok/error stay; the two big strings are dropped); **a TUI-local command is a TURN** — `local: "log"` from the log's own `<command-name>`/`<local-command-stdout>` pair, `local: "screen"` rebuilt from the PTY capture for the ones the CLI never writes down, e.g. `/btw` — and **merging RENUMBERS** (`mergeLocalTurns`: `n` is what the outline lists and the reader scrolls to). Reasoning: [transcript-architecture.md](../../../docs/notes/transcript-architecture.md).
- `ctxwindow.ts` — the most context each model has been SEEN to hold, persisted. **The mark only ever
  RISES**, and is never used raw. A source session's peak is never noted into it: the marks are keyed by claude's ids.
- `tokenstats.ts` · `tokenscan.ts` — every token every conversation on this desktop ever used. `tokenscan.ts` is the disk half: ASYNC, yields every `SLICE_MS` (8 ms), the per-line rules are `tokenstats.ts`'s, and `tokenscan.test.mjs` pins equality with the one-buffer reader. **Store VERSION 6** (5 added `FileSummary.r`; 6 the costliest conversation's first-request tokens) — `FileSummary.r` is the same `isColdRebuild` tally crossed by hour×model (so the premium can be priced per model and day) — present only on files that HAVE one, and the boundary rows are let through the `"usage"` pre-filter by a second substring test, because without them every post-compaction write reads as a cold rebuild. Three rules: **dedupe by `message.id`**, **skip `<synthetic>`**, **keep the four kinds apart for ever**. Subagents ARE counted. Per-file summaries, aggregate DERIVED. **Yields to the event loop every `YIELD_EVERY` (64) reads** — seconds of `readFileSync` are an outage for every live session.
  - The hour×model cross key makes four more projections FREE — no rescan, no version bump: `TokenDay.byModel` (the only form a migration is visible in), `TokenHour.byModel` (the only bucket a LIVE rate-limit window can be cut out of — neither window is a calendar day; the token-stats extension's `web/usageCut.ts`), `TokenGroup.byModel` on the REPO rows (why two repos with equal tokens differ several-fold in cost) and `TokenDay.agents` (subagents STARTED, a count of EVENTS never a slice of tokens; a transcript's launch is its EARLIEST bucket, so a long agent is ONE bar on the day it began).
  - **A repo is `repoOfWorktree(cwd)`**: an agent worktree (`<repo>/.claude/worktrees/<name>`) is its repo's spend, never a repo called `agent-<id>`. **`top`** is the dearest `TOP_CONVOS` (12) conversations with their `subagents/` transcripts FOLDED IN (the agents' slice kept apart as `agentTotals`), priced per record and ranked by money, tokens where nothing was priced.
  - **`windowSeries()` folds the SAME store into PAST rate-limit windows** (`GET /api/tokenwindows`; the token-stats extension's `web/usageCut.ts` draws them as two heat grids): the wire carries a fortnight of hours, the store keeps every hour ever seen, so a weekly window from July can only be answered here. **The GRID is the caller's** (`w=<id>:<anchor>:<len>`, echoed by id). **`windowCells()` is the whole correctness and is exported for its own test** — it REPEATS the live cut's rule (`windowStartHour`: each edge rounded to the NEAREST hour, so cells tile and every hour is in exactly one) rather than re-deciding it; it still answers a LIST so an empty answer needs no sentinel. A window with no row RAN NOTHING; `oldestHour` is what tells that apart from a window the record does not reach. `packages/host/test/tokenwindows.test.mjs`.
- `turnagents.ts` — **per-reader-turn subagent spend**, on the turn that started it: attributed by `toolUseId` / `parentAgentId` off `subagents/agent-*.meta.json` (a lookup, never a guess by time; a nested agent goes where its root went). It READS `agentUsage`'s per-file ledger and never re-tallies, so the last turn's running total equals the header's . A still-running agent is flagged and the figure is then a floor that says so (`AGENT_LIVE_MS` of silence with no ending ⇒ called ended). Degrades to ABSENT: an unreadable directory publishes no agent figure.
- `convlog.ts` — the two decoders the usage-limit reader and the context reader share off the CLI's conversation jsonl. An undated row ⇒ `null`, **never `Date.now()`** . One of the two readers will move first and the other must not quietly disagree — that is why there is one copy.
- `localledger.ts` — claude-local's token ledger and the person's own price table (`GET /api/tokenstats/claude-local`): a CUT of what `tokenstats.ts` already answers — no rescan, no second tally — plus the disk half of the shared user price table (`writeJsonAtomic`, re-read when mtime moves; every failure a sentence). Reasoning: [token-stats-architecture.md](../../../docs/notes/token-stats-architecture.md#local-models-all-backends-and-your-own-prices).
- `claudeconfig.ts` — **the ONE definition of the CLI's private directory**
  (`projects/`, `sessions/`, `settings.json`, `commands/`): `CLAUDE_CONFIG_DIR` replaces the whole directory exactly as the CLI reads it, read at CALL time. Every ledger reader goes through it. `jsonstore.ts`'s `writeJsonAtomic` (tmp + fsync + rename) and `readJsonGuarded` (a corrupt file is moved to `<name>.corrupt-<ts>`, never overwritten) are what every JSON ledger file here (`burnwatch.json`, `billing.json`) writes through; the usage log appends lines (`appendFileSync`) and rewrites via `writeTextAtomic`.
- `usage.ts` · `meter.ts` — the `/usage` capture and the host's own metered calls.
  `usage.ts` is the `/usage` capture: a short-lived `claude` in a PTY on a poll, **RENDERED before it is parsed** (`render.ts` — the TUI's gaps are cursor jumps, not spaces), every field best-effort and `ok:false` when parsing fails, a FAILED probe believed only briefly; gated by halt (`isHalted`/`trackRun`, `halt.ts`). Its reading feeds `usagelog.ts`, `usagesources.ts`, `budget.ts` and the ladder. `meter.ts` is a different thing: the call-count, token and estimated-cost ledger for the API calls waterplane ITSELF makes (plugins, kind `plugin:<id>`; the highlighter's reader, kind `ocr`, is gone and nothing records that kind now), `usage-meter.json`, rolling and capped; an unknown model costs $0 (counted, not priced).
- `billing.ts` · `periodspend.ts` · `billingwire.ts` — **the account model beside the budget.** `billing.ts`: which kind of account claude bills to (`shared/billing.ts` is the classification) — env + `apiKeyHelper` + `claude auth status`, probed at startup and again on demand (`billing.get` with nothing probed yet, or a stale/failed probe), never per request, with a timeout, **`unknown` until that probe has finished** (a guess in the gap would stop the `/usage` poll a subscription needs), a person's override in `billing.json` wins, a failure is `unknown`. `periodspend.ts`: period-to-date DOLLARS folded from `tokenStats.costWindow` , cached because the verdict is synchronous; an entry belongs to the period START it was measured for, so **past the computed reset a cap reads absent and releases with no event**, a stale entry (`SPEND_STALE_MS`, 10 min) is absent, an unscanned ledger is absent, never $0. Labelled "this desktop, list price". `server/billingwire.ts`: the factory that wires them, owns the minute-timer (only while a dollar period exists), `publishBudget` (carries `periods`) and the "$ vs pace" push (`burnwatch.ts` `createPaceWatch`, once per period start, api/cloud only). A known non-subscription profile stops the `/usage` poll; `unknown` polls as before.
- `budget.ts` — the ceiling before the wall. The ONE place that asks `shared/budget.ts`. **An explicit
  send, an ANSWER to a live box, and UPLOADS are never held** — the budget stops unattended work.
- `sessionbudget.ts` — **the per-session budget's calibrator**: one `windowSeries` per `/usage`
  reading (each window from `resetAt − 5 h|7 d` to `checkedAt`), its cost ÷ the window's pct =
  dollars per point (`shared/sessionbudget.ts`'s `sessionBudgetCal`, `weekUsdPerPct`'s rule), handed
  to `sessions.setBudgetCal` and on to `SessionInfo.budget.cal`. Cached on `checkedAt`; a failed fold
  keeps the last figure (it goes stale, and stale is `unknown`). **Never spawns a scrape** —
  `syncUsagePolling` polls while a live session has a percent budget. Hour-wide cells ⇒ "≈".
- **A second backend's store** (opencode's, the first) is read by a STORE READER its extension
  contributes by name (`api.storeReader`, `backends/readers.ts`'s `storeReaderFor`): the reader view
  (`sessions/record.ts`), the context series and tool details (`sessions/ctxseries.ts`'s `storeFor`),
  which conversation a session is in (`sessions/convid.ts`'s `detectBackendId` →
  `PluginStoreReader.discover`, exactly one candidate or none) and its ledger at
  `/api/tokenstats/<id>` (`PluginStoreReader.ledger`, served verbatim). Core keeps the poll contract
  and the watcher's cadence; every answer degrades to ABSENT, and a reader that left (its plugin
  switched off) answers nothing. opencode's readers and their rules: the opencode extension's README
  (`packages/extensions/opencode/`, private, not in the public tree).
- `usagelog.ts` — the `/usage` readings this daemon took, KEPT, so the two limit windows have a
  history. **Nothing is ever scraped for it** — it records what was already fetched. The series is
  therefore IRREGULAR and a gap is a gap, never resampled.  A failed probe
  is DROPPED, not recorded as two nulls; an unchanged reading is kept every `REPEAT_MS` (30 min, `WATERPLANE_USAGELOG_REPEAT_MS`, floor 60 s) anyway.
- `usagesources.ts` — usage readings PER SOURCE beside claude's `UsageInfo` (which stays, untouched, for budget/ladder/burn/plugin API): claude adapted FIRST via `claudeReading`, then each `api.usageProbe` and each backend's own `sources.usage` (`backendUsageProbe`; never `source:"claude"`). A null answer is ABSENT, a throw/timeout keeps the last reading until its reset, every answer vetted (identity is the definition's, out-of-range dropped); one probe in flight, fresh asks behind claude's TTL, polling only by `syncUsagePolling`'s predicate; ONE publisher (`createUsageSources().publish`). Why: host.md.
- `usagesourcelog.ts` — `usagelog.ts`'s rules per source in `usagelog-<source>.jsonl` (claude's file untouched, no migration); `GET /api/usagelog/:source`; a disk row keeps unit+count for the boot `remembered` re-offer.
- `costwindow.ts` — the token store folded over ANY `[from,to)` (`GET /api/costwindow`): by hour,
  repo and conversation, priced per model×day exactly as `aggregate()` . **A window's edge is the phone's `windowStartHour`** (shared, the nearest hour — `windowCells` uses it
  too), sent on the hour so the fold's floor is the identity;
  unpriced tokens are COUNTED, never zero-charged; a subagent folds into its parent. `costMeta`
  JOINS titles (roster, then closed stack) and launches (`runIdOf`: everything before the LAST `#` of `itemId` = fan-out run, absent when there is none);
  a lookup that throws leaves the field ABSENT, and a conversation nobody can name is still a row.
  **Past shared `COST_CONVOS_CAP` (60) conversations fold into `rest`** (repo × launch, no ids) — every total,
  hour and `byRepo` still counts them.
- **Another backend's spend over a span** (`besidespend.ts`, c2): only the `/api/costwindow` ROUTE attaches `beside` — `tokenStats.costWindow` stays claude's fold, and no verdict reads a plugin figure. Cut by shared `ledgerOverSpan` on the ledger's `hourly` rows, never its local days; claude's three backends are skipped (already in the figure); a slow or throwing ledger is an absent sentence.
- `burnwatch.ts` — one `burn` push when the weekly figure climbs past `WATERPLANE_BURN_PTS_PER_HOUR`
  (4; 0 = off), rule in `shared/burn.ts`. **Pushes, never holds; no timer** (`UsageChecker`'s
  callback drives it, and `syncUsagePolling` keeps that poll on while `armed()` and `burn` is
  unmuted); `burnwatch.json` is written BEFORE the push (lose one, never repeat one);
  a cost fold that fails costs the "dearest in it" line, not the push. `createSourceBurnWatch` asks the same rule per non-claude source's `wk`/`mo` window (`burnwatch-sources.json`, claude's file untouched). Why: host.md.
