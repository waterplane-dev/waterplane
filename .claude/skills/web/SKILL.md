**…by symptom**, when you know what is wrong and not which file:

- a prompt ran twice, or never, or went to the wrong session → `web-send`
- the app is offline, the tunnel died, state was lost on reload → `web-send` (outbox) + `web-chrome` (`link.ts`, `resumeRoute.ts`)
- the Android shell, an APK, a download that must survive backgrounding → `web-files`
- something the desktop said is not on screen → `web-term`
- a number on a screen looks wrong → `web-numbers`
- a model, a backend, a setting that will not stick → `web-config`
- waiting work, clocks, builds, the assessment → `web-work`
- a blank sheet, a spinner that never spins, a control needing a reason → conventions below

**Most modules are named by no bullet**: the map covers the ones with a
RULE; the rest follow the conventions below and [web.md](docs/notes/web.md).

**`core/`, `sdk/`, `features/<name>/`**: read
[web-architecture.md](docs/notes/web-architecture.md) and the folder's `README.md` first; a feature
wrapping a module above takes that sub-skill (`features/images` → `-files`).

**The conventions every slice is built on.** These stay in the router because a task
that loads one sub-skill still needs them:

- `storage.ts` — **every `localStorage` key this app owns, in one place**, plus the four readers that
  swallow the private-mode and quota throws once instead of forty times. `SYNCED` is checked against
  `shared/settings.ts`'s allow-list at load. `local/no-storage-key-literal` refuses a new key elsewhere.
- `Sheet.tsx` — `Sheet` and `SheetHead`: 33 files hand-rolling a back button is
  33 chances to get CLOSE wrong.
- `Empty.tsx` — what a list says with no rows: loading/offline/error/nothing plus the age line,
  **which appears above a NON-empty list too**.
- `Unavailable.tsx` — **what a row cannot do, as a sentence, never as a dimmed button** (CLAUDE.md), so a blocked verb is not rendered as a control at all; the button components
  have **no disabled branch**. Tests here must assert the REASON, not a `disabled` attribute.
- `Confirm.tsx` — "are you sure?", once (never `window.confirm`: CLAUDE.md). `ConfirmButton` **disarms itself after `ARM_MS`**;
  `askConfirm()` is mounted in `main.tsx` because `App` returns early per overlay.
- `useRemoteResource.ts` — one host read, told honestly: cache seeded FIRST, live read second, and a
  `state` of `fresh`/`cached`(+age)/`loading`/`error`/`offline`. **The last two are deliberately
  separate.** `offline` takes the SOCKET signal, not `navigator.onLine`. **Cached rows always say how
  old they are.** **`inflight` is a SIXTH fact, not a sixth state** — `loading` means *nothing to show
  yet* and is set ONLY by the first read and a non-quiet `reload`, while every refresh button here
  re-reads quietly or by moving the key, so `state === "loading"` is false from the first paint on and
  two screens shipped a `disabled` that never disabled and then a spinner that never spun. Counted,
  not a boolean (a key change starts the next read before the cancelled one unwinds), decremented in
  a `finally`. **A button that cannot tell whether it is running is the same defect whether it spends
  that on a spinner or on a grey.**
- **The pending session** (`pending:<createAck>`) — **a queued `session.create` IS a session screen.**
  A synthetic `SessionInfo` (id per CREATE, never per repo) renders the real screen with no branch of
  its own. Typing and files need NO new path. What needs a PTY is ABSENT, not dimmed.
- `App.tsx` — the wiring: one call per core hook (`core/*`), `bindCore`; the ws switch is
  `core/conn`'s, the overlay table `core/route`'s. Queue (`core/queue`) is **ref-authoritative** (`local/no-functional-setoutbox`;
  `writeOutbox` is its one writer). **It returns early once per overlay, so an always-on layer
  may not live in it** — `HintLayer` and the toast are mounted in `main.tsx` (state in `hints.ts` / `toast.ts`). **A toast's clock is the LENGTH of its words** (`toastMs`) and **every toast is also a ROW** in a bounded log (`ToastLog.tsx`, *On this phone*) apart from the host's alerts, and NEVER counted into the unread badge. **An explicit send beats
  `holdUntilIdle`**; a busy TURN is not a wall, but a question box, an unparsable dialog and a limit
  block are, and they get NAMED. **Which sheet is on top is a TABLE** (`overlayViews`); a miss returns
  null, falling through to the screen below. **A chatty push nothing on screen reads keeps
  `prev`** — `build.output`, `capture.output` and `assess.state`'s 1.5 s progress frames all guard on
  the overlay, or a 20-minute run is ~800 whole-App renders on every phone; a status TRANSITION, a
  new id or a `null` is NEVER swallowed.
