**…by symptom**: a prompt ran twice, never, or in the wrong session → `web-send`; offline, tunnel died, state lost on reload → `web-send` + `web-chrome`; Android shell, APK, a download that must survive backgrounding → `web-files`; something the desktop said is not on screen → `web-term`; a wrong number → `web-numbers`; a setting that will not stick → `web-config`; waiting work, clocks, builds → `web-work`; a blank sheet or a spinner that never spins → conventions below.

**Adding a feature** — `features/registry.ts` lists every manifest once. New behaviour goes in
`packages/web/src/features/<name>/`, never in App: a manifest that reaches App only through `core()` from `sdk/index.ts` (its members ARE App's own
`liveSend`/`queueOp`/`downloadArtifact`: one socket, one send path).
**`local/feature-boundary` refuses** feature→feature, →`core/` and →`App` imports. Feature
state is `createStore`, ONE writer. **`App.tsx` is a ratchet** (`tools/webshape.test.mjs`
`MAX_APP_LINES`): moving code out lowers it in the same commit; raising it is a decision, never a fix.
Steps ([full](../../../docs/notes/web-architecture.md#adding-a-feature-step-by-step)): name = folder = manifest
`id`, never renamed; `store.ts`, `actions.ts`, `logic.ts` + test, `<Name>Sheet.tsx`, `index.ts`, a 300+ char `README.md`; a line in `registry.ts` and CODEOWNERS; lower `MAX_APP_LINES` if code left App.tsx. A feature wrapping a mapped module takes that sub-skill. An extension remembers via `extStorage(id)`, never `storage.ts`.

**`core/<dir>/`** is what there is ONE of ([table](../../../docs/notes/web-architecture.md#the-core-modules)): `term/` →
`web-term`; `queue/ compose/ send/` → `web-send`; `launcher/ session/ layout/ sessions/` → `web-chrome`;
`settings/ launch/` → `web-config`; `conn/ route/` → here.

- `kit/` — shared controls. **`kit/chips.ts`
  `chipText`/`chipRows` implements CLAUDE.md's "a count is a filter" ONCE** — new count chips call it.
- `sdk/` — an extension's web half imports only `@waterplane/sdk` (the `sdk/index.ts` barrel: `core()`, `createStore`/`useStore`, `usePref`, `pluginClient`, `extStorage`, …), `@waterplane/kit`, `@waterplane/shared`, react(-dom) and lucide-react; a feature imports `sdk` by its index, never `sdk/<file>`.
- `webapi/` — `api.ts` (src root) spreads 9 slices; the folder's other files are helpers. A new endpoint's call goes in the slice of its SUBJECT as a literal
  `/api/...` argument (`demo/contract.test.mjs` reads the AST); raw `fetch` is lint-banned elsewhere.
- `demo/` — never branch UI code on demo; its own chunk, never lazy.

**The conventions every slice is built on** (every task needs them):

- `storage.ts` — **every `localStorage` key this app owns, in one place**, plus the readers that
  swallow the private-mode and quota throws once. `SYNCED` is checked against
  `shared/settings.ts`'s allow-list at load; `local/no-storage-key-literal` refuses a new key elsewhere.
- `Sheet.tsx` — `Sheet`/`SheetHead`: every sheet, never a hand-rolled back button.
- `Empty.tsx` — what a list says with no rows: loading/offline/error/nothing plus the age line,
  **which appears above a NON-empty list too**.
- `Unavailable.tsx` — **what a row cannot do, as a sentence, never as a dimmed button** (CLAUDE.md); the button components
  have **no disabled branch**. Tests here assert the REASON, not a `disabled` attribute.
- `Confirm.tsx` — "are you sure?", once (never `window.confirm`: CLAUDE.md). `ConfirmButton` **disarms itself after `ARM_MS`**;
  `<ConfirmHost />` is mounted in `main.tsx`.
- `useRemoteResource.ts` — one host read, told honestly: cache seeded FIRST, live read second, and a
  `state` of `fresh`/`cached`(+age)/`loading`/`error`/`offline`. **The last two are deliberately
  separate**; `offline` takes the SOCKET signal, not `navigator.onLine`. **`inflight` is a SIXTH fact, not a sixth state**: `loading` means *nothing to show yet*,
  so a refresh button reads `inflight`
  ([story](../../../docs/notes/web.md#moved-out-of-skill-web-2026-10-17)).
- **The pending session** (`pending:<createAck>`) — **a queued `session.create` IS a session screen**: a
  synthetic `SessionInfo` (id per CREATE, never per repo), no branch of its own, no new path for typing or files. What needs a PTY is ABSENT, not dimmed.
- `App.tsx` — the wiring: one call per core hook, `bindCore`. Queue (`core/queue`) is **ref-authoritative** (`local/no-functional-setoutbox`;
  `writeOutbox` is its one writer). **It returns early once per overlay, so an always-on layer may not live
  in it** (`HintLayer`, the toast: `main.tsx`). **A toast's clock is the LENGTH of its
  words** (`toastMs`); every toast except a host alert also lands as a row in the bounded `ToastLog.tsx`, never counted into the unread badge. **An explicit send beats `holdUntilIdle`**; a busy TURN is not a wall, but a question
  box, an unparsable dialog and a limit block are, and they get NAMED. **Which sheet is on top is a TABLE**
  (`overlayViews`); a miss falls through. **A chatty push nothing on screen reads keeps
  `prev`**; a status TRANSITION, a new id or a `null` is
  NEVER swallowed.
