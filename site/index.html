waterplane_ Open source on GitHub

An IDE, rethought for the phone in the age of agentic coding.

The agent writes the code; what you need in your hand is the steering. waterplane drives the real Claude Code CLI on your own desktop, from the next room or, over Tailscale, from anywhere, and puts the workbench around it: files and diffs, commits and builds, the screenshots it makes, a queue and a schedule, and what every turn costs. And it is made to be customized: a plugin adds the button, switch or status line your way of working needs.

Not only on the phone

I wrote waterplane for the phone, and by now it is my preferred environment at the desk too, ahead of VS Code. Open it in a browser on a laptop and it drives Claude Code on a bigger machine elsewhere: the Mac Studio builds and runs the simulators while the notebook only shows the screen. The window gets a sidebar of repos, the session in the middle and a panel beside it, and it is the same sessions, queue and costs, so what you left on the laptop is waiting on the phone.

Desktops can also work for each other. Pair two of them and an agent on one can hand a job to the other (run the Windows build, the tests on the bigger machine): the branch travels through your git remote, the job waits on the other desktop's own queue under its owner's switches, and its answer comes back into the asking session as one prompt.

How it works

A small Node daemon on your machine spawns the real claude binary in a pseudo-terminal and bridges it to a phone app (a web app you add to the home screen, or an Android app). Because it drives the actual binary rather than re-implementing it, every slash command, /btw, the context meter, plan and trust prompts and --continue work as they do at the desk. It drives Claude Code first and foremost (opencode support is experimental). The packages and the plugin mechanism: docs/notes/architecture.md.

What Claude made, on your phone

What Claude leaves in .claude/outbox/ appears on the phone as a picture or a file, with a badge on the repo and a notification. Open it full size, draw a circle or a box on it, type what to change, and the marked-up image goes back into the prompt (it lands in .claude/inbox/). Highlight a line of text to point Claude at it.

When the usage limit hits, it carries on

When a session hits a Claude usage limit, the host notices, waits for the reset and continues it, reopening the conversation with --continue if the CLI exited. Bounded retries, and an off switch per session and for the desktop. To stop before the wall instead, give a session a budget (tokens, dollars, or a share of the 5-hour or weekly window): the next send is held when it is reached, with your words kept and the reason said.

Queue it now, or schedule it against the usage windows

A prompt sent while you are offline or while the session is busy waits in a queue and is typed in exactly once. Or post a prompt for later: at a time, when the session goes quiet, after another one finishes, or anchored to a usage-limit reset ("right after the weekly window comes back", "two hours before the reset, spend what is left"). The Backlog holds a repo's work that nobody has started.

Know what it costs

Every finished turn says what it cost: tokens in, out and cached, and dollars at list price, plus what the next turn will cost compared with a fresh session. The token ledger splits every total by day, repo and model; the header carries the 5-hour and weekly usage windows with their resets; each session has a context sheet showing how full the window was over time and where it compacted, and on a fan-out session what its subagents cost, each one as a bar, the skills they loaded and what every turn carries before your prompt. A per-repo check weighs CLAUDE.md and skill descriptions, the part every turn pays for again. All read off the CLI's own logs and screens; where there is nothing to read, nothing is shown rather than a guess.

Repo health, so the vibe coding stays maintainable

Vibe coding drifts into a mess quietly, and a steady number does not mean a healthy repo. Each repo gets one health score out of 100, measured against fixed good values: file length, files reworked right after an edit, unexplained escape hatches (eslint-disable, as any), untested modules and the CLAUDE.md weight. The worst reading caps the score, so one giant file cannot hide behind four quiet readings, and each warning names the file behind it. The trend since the first week comes second. A push arrives when a reading newly turns severe. The film shows the shape of a real app vibe-coded for months with none of this: one file grew to 8,397 lines, and the score says 46. These are readings only: nothing changes code on its own.

Your own buttons: plugins

When the built-in buttons do not fit how you work, add your own. A plugin is a small folder outside this repo (~/.config/waterplane/plugins/) with a manifest and a host.mjs; it declares action buttons (in its Settings section or a session's menu), settings fields, per-session switches, a badge or a status line, and the app draws them with its own components. No fork, no core edit, and it keeps pulling upstream. How to install one, the template to start from and the list of plugins: docs/plugins.md; every published plugin is under the waterplane-plugin topic. The contract: docs/plugins-api.md; why it is shaped this way: docs/notes/plugins.md.

Build an APK, and other phones install it by themselves

Android app developers only (optional).

Save a build command per repo and run it from the phone without a Claude session, so it spends no tokens; it is the way out when you are rate limited and still need a build. Produced files are detected and downloadable. With the developer build of the Android app, a phone you opt in installs each new APK of your app by itself.

Install

Read this before you install it.

The daemon spawns claude, which can read, edit, and execute files on your machine. There is no app-level login by default: the security boundary is the network. Anyone who can reach the daemon can, in effect, use your computer.

By default it binds only loopback and your Tailscale IP, and refuses to bind LAN or public addresses unless you explicitly set WATERPLANE_ALLOW_PUBLIC=1 (which then requires a password for LAN devices). Keep it that way. Point it only at code you trust. SECURITY.md has the full threat model, and DISCLAIMER.md covers what else you are agreeing to: arbitrary code execution, what leaves the machine when you pick a hosted model, and what a free tier is actually paid with.

Unofficial.

Not affiliated with, endorsed by, or supported by Anthropic. This project ships no Anthropic code: it invokes the claude CLI you installed and are logged into. It works by wrapping that CLI's terminal, which means it reads TUI output with regexes and uses flags that change between Claude Code versions. Expect it to need updates when claude updates. Currently tested against claude 2.1.x.

You use your own account, under your provider's terms. Queued, scheduled and resumed-after-limit runs start sessions without you at the keyboard; whether your plan allows that is between you and the provider — see DISCLAIMER.md.

You need:

  • Claude Code installed (curl -fsSL https://claude.ai/install.sh | bash, or npm install -g @anthropic-ai/claude-code), and something for it to run on: a paid Claude plan (Pro, Max, Team) or an Anthropic API key — run claude once and sign in — or, with no account, a local model through Ollama. GitHub Copilot works too, as a plugin (install.sh --with copilot).
  • A way for the phone to reach the desktop. Recommended: Tailscale on both, on the same tailnet. It works from anywhere, its device sign-in is the gate, and its HTTPS gives the phone push, install and clipboard. From the same Wi-Fi or over a VPN of your own, a password does the gating instead: without Tailscale. With neither, the daemon binds loopback only and is reachable just from the desktop.

The installer (macOS, Linux, WSL2) brings its own pinned Node, verifies checksums, and adds a waterplane command with start, doctor, service, update and pair:

curl -fsSL https://github.com/waterplane-dev/waterplane/releases/latest/download/install.sh | sh

Or from source, which also needs Node ≥ 22.12 and tmux 3.3+ (every session runs inside it, so it survives a host restart; the installer handles both). The doctor builds what it checks, so it runs before the build:

git clone https://github.com/waterplane-dev/waterplane.git
cd waterplane
npm ci             # installs the lockfile exactly; runs no dependency install scripts
npm run doctor     # checks claude login, node-pty, tmux, Tailscale, HTTPS, port
npm run build
npm start

npm run doctor (or waterplane doctor) is the first thing to re-run when something misbehaves: it names what is wrong and what to type. The host lists the git repos under ~/dev (or WATERPLANE_ROOT; the doctor says which folder) and prints its address. Plain http://100.x.y.z:8770 works for a first look; for install, push and clipboard on the phone, enable HTTPS + MagicDNS in the tailnet admin console once, then open https://<machine>.<tailnet>.ts.net:

tailscale serve --bg --https=443 http://127.0.0.1:8770

Or use the Android app, which needs no HTTPS: the APK is on the latest release.

Windows, Docker, agent install, notifications, a second phone or desktop, the background service, updating and every environment variable: docs/install.md.

How it compares

Anthropic's own Remote Control now drives a local Claude Code session from the Claude app, and Happy, Paseo and Orca put coding agents on a phone too. Reaching your agent from a phone is not what is different here. What is: the real terminal plus a reader, no vendor or relay in the path, the build and artifact loop back to the phone (marked-up screenshots into the prompt, verified simulator and device screenshots, APKs onto your own phone), schedules against usage windows with an exactly-once queue, token and cost history with the next turn's price, repo health that keeps that price flat, and plugins for the buttons nobody else ships.

Nor is it a chat agent. OpenClaw and similar assistants can run Claude Code for you headless and report back in a message, which is enough for "go do X". waterplane is the more comfortable path, with more control where you want it: drive the session yourself (the live terminal, the boxes it asks, the diff before the commit) or leave it to the queue and the schedule. And because every turn's cost is in front of you, it is where you save tokens, time and money when you want to.

It is not either/or with Remote Control. Turn on the launch option "Remote Control" and every session waterplane starts is also reachable from the Claude app: waterplane to start sessions on any repo, read, build and schedule; the Claude app for a quick look when it is the app already open.

The short table is docs/notes/compare-table.md; the long, cited version is docs/notes/vs-competitors.md. Where waterplane loses, plainly:

  • No native iOS app yet. iPhone gets the web app (not yet tested on a real iPhone); Android gets a native app as well.
  • One user. No team, no shared sessions.
  • Away from home it needs a tailnet, or a VPN of your own. Tailscale is the recommended path and the one the setup assumes; the same Wi-Fi works with a password, minus push and install.
  • Anthropic ships more of the phone surface every release, and the TUI it reads can change.
